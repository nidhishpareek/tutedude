Linux — lecture notes

This course is a spoken walk-through of Linux for someone who will work on a server, mostly Amazon Linux 2023 on a small AWS EC2 instance. It starts with what an operating system is, then how to get a Linux machine (virtualization and EC2), then the file system, everyday commands, users and permissions, processes and packages, shell scripts, networking and servers, and disk, boot, and storage. Two short units at the end are about a resume and interview questions.

Watch the folders in number order. Unit 01 is only the Tutedude website. Unit 02 is the map of the course. Real Linux starts at unit 03. Hands-on lectures assume you are on an EC2 terminal, usually as root after sudo su. Package commands on Amazon Linux 2023 are dnf. The same ideas on Ubuntu are apt-get.

Unit 03

Introduction To Linux

003 — Section 1 Overview

  • This section is the introduction only: what Linux is, how it started, key features, and distributions.
  • Distributions are the variants that grew out of Linux.
  • He also flags a comparison with other operating systems. No commands yet.

Distribution. A Linux variant built from Linux, also called a distro.

004 — Introduction To Linux

  • Linux is a free, open-source operating system used on servers, cloud machines, embedded devices, and some desktops.
  • An operating system sits between hardware and the person using the machine. He lists what it manages: processes (scheduling, multitasking, processes talking to each other), memory (how much RAM a process gets, including paging), the file tree, devices such as keyboard, mouse, and network gear, security, the user interface, and the network.
  • Security pieces he names: login, how much access a user has, encryption with keys, and logs of who did what and when.
  • Linux in this course is a command line. Windows is mostly a graphical desktop, with a command shell that few people use. He mentions HTTP on port 80 and HTTPS on port 443 as traffic the OS handles.
  • A machine with CPU, RAM, and disk still needs an OS. Without one it does not run software.

Operating system. System software that connects hardware and the user and runs processes, memory, files, devices, security, and the network.

File system. The hierarchy of folders and files where data is stored, with access rules and a type such as EXT4 or NFS.

CLI. A command-line interface: you type commands instead of clicking icons.

005 — Key Functions, Linux Distributions And History

  • He recaps OS jobs (process, memory, files, devices, security, network) and names examples: Linux, Windows, macOS, Unix, and Android.
  • Linux is Unix-like. The kernel source is open, so people can change it and ship their own versions. He ties that to servers and cloud, not to home desktops.
  • Distros he names on a slide: Ubuntu (has a desktop as well as a shell), RHEL from Red Hat (certifications for admins), Amazon Linux on AWS EC2, CentOS (older, less used now), and Debian.
  • He places Linux on servers, data centers, AWS, Azure, and Google Cloud, supercomputers, Android, and in DevOps and system-admin jobs.
  • History on the slide: Linus Torvalds, a Finnish student, wrote a free kernel in 1991 as a hobby, released it under the GNU GPL, and GNU tools made it a full OS. Red Hat, IBM, Intel, and Google later backed it.

Kernel. He uses the word for the core of the system; the next lecture defines it. Here, Linux is “based on the Linux kernel” and the source is public.

EC2. Elastic Compute Cloud, the AWS virtual machine he will use as the lab server.

006 — Linux Vs Unix

  • Linux: free, open source, Unix-like, started by Linus Torvalds in 1991, community-driven, used on servers, cloud, supercomputers, embedded devices, and desktops.
  • Unix: a family of proprietary systems from the late 1960s at AT&T Bell Labs, built for stability, multitasking, and many users, mostly in older enterprise setups.
  • Shared ideas: similar commands, a similar directory tree, multitasking, and multi-user use. Differences he puts in a table: license and cost (Linux free, Unix paid), who develops it, hardware (Linux on almost anything, Unix often on vendor hardware), how much you can change, update speed, and cloud use.
  • Unix names on the slide: AIX, Solaris, HP-UX. Linux names: Ubuntu, RHEL, CentOS Stream, Amazon Linux 2023 (the one this course uses).
  • Linux can be a shell or, as with Ubuntu, a shell plus a graphical desktop. Unix is mainly a command line.

007 — Linux Flavours

  • A flavour, distribution, or distro is a Linux version built around the same kernel, plus its own tools, package manager, and sometimes a desktop.
  • He explains the kernel as the core program of the OS, the bridge from software to hardware, and the reason a new laptop already has tens of gigabytes used.
  • Family line he draws: Debian from the Linux kernel, Ubuntu from Debian, Linux Mint from Ubuntu for people who want a Windows-like desktop.
  • Ubuntu: free, beginner-friendly, package manager apt. RHEL: paid, corporate servers, yum and dnf, sold on stability, security, and scale. CentOS was a free build from RHEL and is discontinued; CentOS Stream 9 is a rolling preview used to test before RHEL.
  • Amazon Linux 2023 is the distro for this course: free, long support from AWS, used for EC2, and also reachable by SSH from other tools. Debian is stable and light but less current. Fedora tracks new features and is used to try things before RHEL. SUSE is another paid enterprise distro (zypper). Arch is minimal and rolling, for experienced users (pacman). Kali is for security testing and penetration testing, with security tools already installed.

Kernel. The core program of the operating system that links software to hardware.

Package manager. The tool a distro uses to install software. He names apt, yum, dnf, zypper, and pacman.

008 — Linux Flavours Tabular Comparison

  • He walks a comparison table: best use, package manager, and who it is for.
  • Beginner desktops: Ubuntu and Linux Mint, because they have a graphical interface. Cloud: Amazon Linux 2023. Testing and developers: Fedora and CentOS. Advanced: Debian and Arch. Security work: Kali. Paid enterprise: SUSE and RHEL.
  • He tells you to remember two less common managers for interviews: SUSE uses zypper, Arch uses pacman. RHEL is the one that still has both old yum and new dnf.
  • Short “main use” column: Ubuntu for desktop, server, and cloud; Mint for desktops; Kali for security testing; Arch for custom systems; SUSE and RHEL for enterprise; CentOS for testing RHEL-like servers; Amazon Linux next to AWS; Debian for stable servers; Fedora for newest features and testing.

009 — Linux Users

  • A user is an account for a person, a service, or a process. Many users can be on the system at once, with their data separated.
  • Each account has a user id and one or more group ids. Root is uid 0 and can change the system, install software, and manage users. Normal users are uid 1000 and above. System users sit below 1000, do not log in at a prompt, and exist so a service such as a web server or database runs as its own account.
  • A normal user who is allowed to act as admin prefixes the command with sudo. His example is sudo dnf install nginx -y versus the same command as root without sudo.
  • Permissions are read, write, and execute, applied at three levels: the user, the group, and everyone else.

Root. The superuser account, user id 0, with full control of the system.

sudo. “Super user do”: run one command with admin rights, if that account is allowed to.

010 — Linux Vs Windows

  • He compares license, security, how much you can change, and where each is used. Linux source can be read, changed, and shared. Windows is closed and controlled by Microsoft.
  • Table he fills in: Linux free and highly changeable, Windows paid and limited; Linux strong on servers because of permissions and fewer malware targets; Windows fine for desktops, office software, and games.
  • Install method: Linux uses apt, dnf, or yum. Windows uses .exe and MSI installers. Shell: bash on Linux, Command Prompt and PowerShell on Windows.
  • Updates on Linux are something you choose to run. Windows can update itself. Linux is the usual OS for servers, cloud, and DevOps. Games run on Windows; Linux is for hosting, not for playing those games on the desktop.

  • Billing asks for a debit or credit card. The slide says usage under free-tier limits is not charged, and AWS may place a temporary hold of about one US dollar for a few days to check the card.

Root user (AWS). The first account owner. He sets that password during signup. This is the AWS account root, not the Linux root, though he uses the same word.

Unit 04

Virtualization

012 — Section 2 Overview

  • This section is what virtualization is, the types, and AWS virtualization.
  • He says most Linux systems people use today are virtual machines, so the idea matters before the commands.
  • No terminal in this overview.

013 — Virtualization

  • Virtualization makes software copies of servers, operating systems, storage, and networks on one physical machine. He uses a building: one computer is the building, each virtual machine is a flat with its own OS, and they do not disturb each other.
  • The split happens in the hypervisor, which sits between hardware and the virtual machines and hands out CPU, RAM, disk, and network.
  • Worked example: a laptop with 1 TB SSD and 8 GB RAM gives a learning Linux VM about 100 GB and 1 GB RAM, and no graphics card, because this course’s Linux has no desktop.
  • Parts of a VM: a guest OS, virtual CPU, virtual RAM, virtual disk, and a virtual network adapter.
  • Order he draws: divide the hardware, install a hypervisor (VirtualBox, KVM, ESXi), create the VM with those resources, install the guest OS, then run it. Type 1 hypervisors sit on the hardware (KVM, ESXi, Hyper-V). Type 2 sits on a host OS (VirtualBox, VMware Workstation).

Virtual machine. A software computer that runs its own OS and apps on a share of real hardware.

Hypervisor. The layer that splits physical CPU, memory, disk, and network across virtual machines.

014 — Virtualization Types

  • Server virtualization: many virtual servers on one physical server. Each has its own OS, CPU, RAM, and disk. Used in data centers and on AWS EC2. Difference from a laptop VM: on AWS you rent the hardware in their data center, you do not own the box.
  • OS virtualization: containers (Docker, Kubernetes, Podman) share the host kernel. They start faster and use less than a full VM, with slightly less isolation. A container is not a second full machine.
  • Desktop virtualization: the desktop you use is hosted on a central server and you reach it over the network. His example is driving a large EC2 from a laptop so a website does not have to live on the laptop.
  • Storage virtualization: many disks look like one pool. Everyday example he gives is Google Drive; the industrial one is Amazon S3. Snapshots and extra copies are part of this idea.
  • Network virtualization: virtual switches, routers, firewalls, and VLANs in software. Application virtualization: an app runs in its own bubble (containers, or Microsoft App-V) so it does not install straight onto the host. He says the app needs to be reachable over the network.

Container. An isolated environment that shares the host kernel instead of booting a full extra OS.

015 — Virtual Box

  • VirtualBox is free software that runs extra operating systems on the computer you already own. It does not launch a new cloud server. It is a type 2 hypervisor on top of Windows, macOS, or Linux.
  • Each guest gets its own virtual CPU, RAM, disk, and network, and behaves like a separate computer. Guests he names include Windows, Linux, and BSD.
  • Features on the slide: snapshots (a saved state, like a game save), shared folders, USB, networking modes NAT, bridged, and host-only, seamless mode, and a shared clipboard.
  • He contrasts isolation with “everything on one OS”: a problem in one VM stays in that VM. Cost is zero for the tool; you already paid for the PC. Performance is a bit lower because the hardware is shared.
  • Uses he lists for this course if you were not on AWS: Amazon Linux 2023, disk partitioning, RAID, NFS, packages, and admin commands.

Snapshot. A saved backup of the virtual machine at one moment, so you can return to that state.

016 — Aws Virtualization

  • The lab plan: cheap EC2 instances, Amazon Linux 2023, because it matches current cloud work better than an old CentOS plus VirtualBox setup.
  • AWS is Amazon’s cloud: on-demand compute, storage, and databases. He sketches regions as dots, each a set of data centers full of physical servers. Hypervisors on those servers carve out CPU, memory, disk, and network. You ask over the network; you get a VM that feels like a server but shares the host, isolated from other customers.
  • EC2 is the compute service: pick an OS, CPU, RAM, and storage, launch in minutes, scale up or down, pay for hours used. The modern hypervisor is Nitro (older instances used Xen). Nitro moves virtualization work onto dedicated hardware so isolation is strong and speed is close to bare metal.
  • Other virtualization on AWS: EBS volumes as the virtual disk, S3 as object storage, VPC for subnets, route tables, security groups, and internet gateways, and containers through ECS, EKS, and Fargate.
  • He also mentions bare-metal EC2 (no hypervisor exposed) for special jobs, many regions and availability zones, and that you do not repair the physical RAM or cooling yourself.

VPC. Virtual Private Cloud: the software network on AWS (subnets, routes, security groups, gateways).

EBS. Elastic Block Store, the virtual hard disk attached to an EC2 instance.

017 — Understanding Ec2

  • EC2 is the AWS service that gives you a virtual server. He prefers it over VirtualBox for this course because companies host apps on EC2, and a new account’s free tier can keep a tiny instance at no charge. He warns that a non-free account still bills, and a wrong size can make a large bill.
  • You choose the OS, CPU, and storage, change the size later, and pay for what you run.
  • Instance families: general purpose T or M (balanced CPU, memory, network; small web apps). Compute optimized C (batch, game servers). Memory optimized R or X (in-memory databases, big data, cache). Storage optimized I or D (databases, warehouses, logs; I for high IOPS, D for disk). Accelerated P, G, or F (GPU, machine learning, video). Those last ones are expensive and not used here.
  • Name reading: T3 micro means family T, generation 3, size micro. T3 is the newer generation of T2. This course uses T2 micro or T3 micro.
  • He says a later lecture in the section shows the launch clicks. This lecture is the size chart, not the launch itself.

Instance type. The hardware shape of an EC2 VM: how much CPU, RAM, storage performance, and network it gets.

018 — Understanding Amis

  • An AMI is a template for an EC2 instance: OS, software already installed, settings, and the root disk, so you do not configure every boot from scratch.
  • You can launch without one, but he says an AMI is the normal way. This course uses the Amazon Linux 2023 AMI. Other examples on the slide: Windows Server, macOS, and images from the marketplace (Apache, Nginx, Docker), some free and some paid.
  • You can bake your own AMI and even sell it on the marketplace.
  • Why he cares: servers come up faster, many instances stay identical, snapshots make backup and recovery easier, and scaling is simpler. A few lectures may use Ubuntu instead, which is still Linux.

AMI. Amazon Machine Image, a ready-made template used to launch EC2 instances.

  • Drawing a hypervisor under several VMs, then the six virtualization types, then VirtualBox as a type 2 tool on your own PC.
  • Mapping AWS pieces: region, data center, Nitro, EC2, EBS, S3, VPC, ECS, EKS, Fargate.
  • Reading the EC2 family letters and the AMI idea. The account was created in the previous unit; the repeated launch clicks start in the next units.

Unit 05

System Access & File System

019 — Section 3 Overview

  • This section is the Linux directory tree, how to move around it, how to make and delete files and folders, wildcards, and copying.
  • He calls these the first real skills for any Linux machine.
  • No commands are typed in the overview itself.

020 — File System Structure And Description

  • He walks the top of the tree, each name under /.
  • /bin user commands. /boot bootloader files (kernel, init, GRUB). /dev device files for disks, USB, terminals. /etc configuration. /home normal users’ home directories. /lib and /lib64 libraries needed by /bin and /sbin.
  • /opt optional add-on software. /proc virtual files about the kernel and processes. /root the root user’s home, not the top of the tree. /run runtime data such as process ids and sockets. /sbin admin commands.
  • /srv data for services such as web and FTP. /sys kernel and device interface. /tmp temporary files, cleared on reboot. /usr user programs, libraries, and docs. /var logs, spool files, and caches that change often.

Root directory. /, the top of the Linux file tree. Not the same folder as /root.

021 — Navigation Through Files

  • Three commands: cd to change directory, pwd to print the directory you are in, ls to list names in the current directory.
  • An absolute path starts with / and is the full chain from the top, for example cd /var/log/samba.
  • A relative path does not start with /. It is from where you already are: cd var, then cd log, then cd samba.
  • He says a long chain is faster as one absolute path, because you do not type cd at every step.

Absolute path. A location that starts at / and does not depend on the folder you are in now.

Relative path. A location written from the current directory, with no leading slash.

022 — File Navigation Hands On

  • On an AWS Linux terminal he runs pwd and sees /, then ls -l / and the top-level directories appear.
  • cd bin, ls -l shows the command files, then a bare cd returns him to /. He checks with pwd.
  • He enters media and home; ls -l is empty because nothing is mounted or no user files are there. cd /var and ls -l shows folders, then he goes into tmp.
  • clear wipes the screen. He notes this is a cloud t2 micro, but the same three commands work on any Linux tree.

023 — Relative And Absolute Paths Hands On

  • pwd confirms he is in /. Absolute jump: cd /var/log. The prompt and pwd both show /var/log.
  • Back with cd /. Relative version: cd /var, then cd log with no slash, then cd journal.
  • cd samba from that log folder prints “no such file or directory” because samba is not there. He uses journal instead to show a relative step that exists.

024 — Creating Files And Directories

  • Create an empty file with touch filename. Several names in one line make several files: touch file1 file2.
  • Create a directory with mkdir name. Same pattern for several directories.
  • cp source newname duplicates a file, so the copy is a new file. Example: cp file1 newfile1.
  • vi filename opens the visual editor and can create the file as well. The editor keys come later.
  • If the shell says permission denied, he says try sudo chmod for now; chmod is taught properly in the next unit.

025 — Removing Files

  • rm filename removes a file. rm -r directory removes a directory and what is inside it.
  • rm -f deletes without the yes or no question. Without -f, the shell asks and you answer y or n.
  • truncate is different: it empties the contents and leaves the file in place. He introduces the name here; the full demo is later.

026 — Creating Files Hands On

  • The recording is a wildcard drill that starts by creating files. pwd and ls -l in /, then mkdir nd and cd nd.
  • touch makes abc, abcd, longer names, and file1 through file5. ls shows them.
  • ls abc* lists names starting with abc. ls abcd* drops the shorter abc. rm abcd* and he answers yes; those names are gone.
  • He makes names containing “cat”, tries rm *cat*, and answers no so they stay. rm a* and rm f* clear groups. touch abc{1..9}xyz style numbering creates nine names at once, then rm a* removes them.
  • ? is one character: ls ?cat matches acat, bcat, ccat, dcat. * is any length, including empty.

Wildcard. A stand-in character in a name: * for any run of characters, ? for exactly one.

027 — Creating - Removing Files And Directories Hands On

  • pwd is / and ls is empty of his own folders. mkdir dir1, ls shows it, cd dir1.
  • touch file1, ls, then rm file1 and he types y. ls is empty again.
  • touch file1 file2 file3 creates three files. rm file1 file2 file3 asks once per file.
  • Back at /, rm -r dir1 and yes removes the directory. clear, then ls shows it gone.

028 — Wildcards

  • A wildcard stands in for characters so one command hits many names.
  • * is zero or more characters. ls -l file* lists file1, file2, and so on.
  • ? is exactly one character, so it will not match a longer tail the way * does.
  • Square brackets are a range. His create example is names abcd1xyz through abcd9xyz from one touch with a range.
  • He points at the terminal for the live version, which is the next lecture (and was also practiced in 026).

029 — Wildcards Hands On

  • Same drill as 026, from /: mkdir nd, cd nd, touch the abc series and the file series, clear when the screen fills.
  • ls -l abc* and ls -l abcd*, then rm abcd* with yes. New files with “cat” in the name, rm *cat*, and he answers no, then later yes.
  • One touch with a number range builds abc1xyz through abc9xyz. rm a* or rm *xyz clears them.
  • ls -l ?cat shows only names with one character before “cat”. rm with the same pattern deletes them. ls at the end is empty.

030 — Soft And Hard Links

  • He ties both links to an inode: a pointer, or the number of the file on disk.
  • A soft link breaks if the original file is removed or renamed. A hard link still reaches the data if the original name is deleted, renamed, or moved.
  • Commands on the slide: ln for a hard link, ln -s for a soft link, then the file name. A hard link points at the inode. A soft link points at the path.
  • This lecture is the definition. He says the typing is on the command line next, but the caption stops at the idea.

Inode. The on-disk record that points at a file’s data. Names are labels on that record.

Soft link. A shortcut to a path. Remove or rename the file and the shortcut fails.

Hard link. Another name for the same inode. Deleting one name does not delete the data while another name remains.

031 — Find & Locate Command

  • find and locate both search for files and directories. Simple form he writes: find filename and locate filename.
  • If locate prints nothing, become root and run updatedb so the search database is current. Also install the package: yum install mlocate.
  • locate reads that database, so it is faster and can be wrong if the database is old. find walks the directories now, so it is slower and current.

032 — Copy Command

  • cp copies files or directories on the same machine. Uses he names: a duplicate, a backup, or moving data between folders without a network copy.
  • Shape: cp, options, source, destination.
  • cp -r is recursive, required for a folder and everything inside. -i asks before overwrite. -p keeps timestamps and permissions. -v prints each file as it is copied.

033 — Copy Command Hands On

  • From /, mkdir directory1, cd directory1, touch file1. Then cp file1 copyfile1. ls shows both.
  • Back at /: cp -r directory1 /var/copydirectory1. He cds into the copy and ls shows the files came along.
  • rm -r on the copy asks before descending, emptying, and removing. The original directory1 still has file1 and copyfile1. He then removes the original the same way.

  • Naming the standard directories, then on an EC2 shell using pwd, ls -l, cd, and clear to walk /, /bin, /var, and /var/log.
  • Creating and deleting files and folders with touch, mkdir, rm, and rm -r, including yes/no prompts.
  • Filtering names with *, ?, and a brace range, then copying a file and a directory with cp and cp -r.

  • Move with absolute and relative paths and read pwd to check.

  • Choose find or locate, and explain a soft link versus a hard link.

Unit 06

Linux Fundamentals

034 — Section 4 Overview

  • Fundamentals he lists: file editing, permissions, access control, and compressing and uncompressing.
  • He calls this the everyday set every Linux user is expected to know.
  • The terminal work starts in the next lecture.

035 — Command Syntax

  • A command line is three parts: the command (the program, such as ls or find), options that change it (usually - or --), and arguments (what it acts on: a file, a directory, a user).
  • Example he writes: ls -la /var/log. ls is the command. -la is -l plus -a written together. -l is the long listing. -a includes hidden names. /var/log is the argument.
  • The result is every file and directory in that folder, with details.

Option. A flag after the command, starting with a dash, that changes how the command behaves.

Argument. The target of the command, usually a path, file, or user.

036 — Command Syntax Hands On

  • In / he runs ls, then ls -l for the long list, then ls -la for the long list including hidden names.
  • ls -l /var lists /var without cd into it. That path is the argument.
  • He opens man ls. The manual shows the synopsis ls [options] [file], then options from -a onward, including -l as the long format. He says there are too many flags for one lecture and you should try them.

037 — User And Permission Management

  • whoami prints the logged-in name. On this EC2 it prints ec2-user unless he has switched to root.
  • Three permission letters: r read, w write (change the file), x execute (run a program or script). They are set three times: user, group, others. In ls -l, a leading - is a file and d is a directory. A dash in a permission slot means that right is missing.
  • chmod changes mode. Letters: u user, g group, o others, a all. chmod g-w file removes group write. chmod a+x file adds execute for everyone. chmod a+r+w+x file adds all three for everyone.
  • Numbers: 0 none, 1 execute, 2 write, 4 read. Add them: 3 is write+execute, 5 is read+execute, 6 is read+write, 7 is all. Three digits are user, group, others. chmod 000 file locks it. chmod 777 file opens it to everyone, which he says is rare on a real system.
  • Ownership: chown user file changes the user owner. chgrp group file changes the group. -r does it recursively. Check with ls -l.

chmod. Change the read, write, and execute bits on a file or directory.

038 — Chmod Hands On

  • ls -l in /: directories start with d, then three rwx groups. He makes mkdir nd, cd nd, touch file. A new file has no user execute, and no group or other write or execute.
  • chmod u+x file adds user execute. ls -l shows x, and the name turns green. chmod u-x file removes it and the green goes away. Group write chmod g+w file does not turn it green. Execute at any level does.
  • One letter at a time is slow. chmod g+r+w+x file adds all three for the group. chmod g-r-w-x file takes them back.
  • Numbers: chmod 000 file clears every bit. chmod 777 file sets rwx three times. chmod 642 file is user read+write (6), group read (4), others write (2).

039 — Chown Hands On

  • In nd he touches file1 and file2. ls -l shows owner root and group root.
  • chown ec2-user file1 changes only the user owner. The group stays root.
  • chgrp ec2-user file2 changes only the group on file2. User stays root.
  • He puts both back: chown root file1 and chgrp root file2. A typo in chgrp fails until he retypes it. ls -l confirms.

040 — Help Command + Hands On

  • As root he runs ls --help. It lists options. q leaves that view.
  • man ls is the manual: what the command is, how to use it, then the options. He says the manual is fuller than --help. q exits.
  • info ls is longer still, with paragraphs and examples. q exits.
  • whatis ls is one sentence. If it says “nothing appropriate”, he runs sudo mandb or installs the man database with yum. He then tries whatis on yum, rm, and touch.

041 — Input And Output Redirections Hands On

  • He creates output.txt with touch. echo hello linux > output.txt writes the line and replaces whatever was in the file. A second echo with >> appends another line.
  • wc -w < output.txt counts words by reading the file as input. His result follows the lines he echoed.
  • Errors: ls wrongdir 2> error.log sends the error into the file. 2>> appends another error. &> sends normal output and errors to the same place.
  • echo linux rocks | tee output.txt shows the text on screen and writes it to the file.

Redirection. Sending a command’s output or input to a file: > overwrites, >> appends, < reads a file in, 2> catches errors.

042 — Executing Multiple Commands With Hands On

  • Commands separated by ; each run even if an earlier one fails. He runs ls ; pwd ; whoami and sees the listing, /, and root.
  • He chains a write and a read: echo hello linux > hello.txt ; cat hello.txt, then again with “hello world”.
  • A longer chain: sudo dnf update -y ; df -h updates packages, then shows disk use. He says the dnf and df flags are explained later; this lecture is only the chain.
  • Shell scripts are another way to run many commands. That is two units ahead.

043 — Acl (Access Control List)

  • An ACL is extra permissions on a file or directory, beyond the three rwx sets.
  • Normal mode only has owner, group, and others. An ACL can give Alice read and Bob write on the same file and leave the group and others bits as they were.
  • This lecture is the reason. The commands are next.

ACL. Access control list: a list of extra users or groups and the rights each one has on a file or directory.

044 — Acl Basic Commands

  • Check that ACLs are on: mount | grep acl.
  • getfacl filename prints the list. setfacl changes it.
  • setfacl -m u:alice:r file.txt gives Alice read. -m g:developers:rw file.txt gives a group read and write. -x removes an entry. -m modifies or adds.
  • Default ACL on a directory, so new files inherit it: setfacl -d -m u:alice:rw projects.

045 — Acl Hands On

  • mount | grep acl returns lines, so ACL support is already there. If not, sudo yum install -y acl.
  • touch demo.txt, echo a line into it, getfacl demo.txt. Owner and group are root.
  • setfacl -m u:ec2-user:rw demo.txt. getfacl now shows ec2-user with read and write.
  • setfacl -x u:ec2-user demo.txt removes that entry. The next getfacl has no ec2-user line.

046 — Tab Completion And Up Arrow Keys With Hands On

  • Tab after a partial command lists matches. ch then Tab shows chgrp, chmod, chown, and more. Twice if one Tab is not enough. ls plus Tab lists commands that start with ls.
  • cd /v then Tab completes /var because only one directory starts with v. cd /s then Tab shows sbin, srv, and sys and waits for you to finish the name.
  • Up arrow walks back through commands you typed. Down arrow walks forward. history prints the numbered list.
  • !! runs the last command again. !56 runs history item 56. !! is stored in history as the command it repeated, not as the two exclamation marks.

047 — Linux Pipe With Hands On

  • A pipe | sends the output of the first command into the second. ls -l | grep .sh lists, then keeps only names ending in .sh. At first nothing matches. After touch hi.sh, the same pipe prints that file.
  • He creates /var/log/messages with touch, then cat /var/log/messages | wc -l. The count is 0 because the file is empty.
  • A longer pipe: cat /etc/passwd | cut -d: -f1 | sort | uniq prints unique user names, one per line (root, ec2-user, and the system accounts).

Pipe. The | character. The output of the command on the left becomes the input of the command on the right.

048 — Compressing & Uncompressing.Mp4

  • tar bundles files into one archive. Flags add compression. He says it began as a tape backup and is now the usual Linux bundle.
  • Flags: c create, x extract, z gzip (fast), j bzip2 (smaller, slower), v show names as it works, f the archive file name.
  • Create: tar cvzf archive.tar.gz myfolder. Extract: tar xvzf archive.tar.gz.
  • zip -r myfiles.zip folder and unzip myfiles.zip are the pair that Windows also understands. -r is required for a folder.

tar. A command that packs files into one archive. Compression is a separate flag such as z or j.

049 — Compressing And Uncompressing Hands On

  • mkdir tar/demo from /, then two echo ... > tar/demo/file1.txt lines (and file2). He has to be in /, not inside the folder, for the tar path he typed.
  • tar cvf archive.tar tar/demo creates the archive and lists the files. tar tvf archive.tar lists what is inside without extracting. tar xvf archive.tar extracts.
  • gzip archive.tar replaces it with archive.tar.gz. ls -lh archive.tar.gz shows the compressed size. gunzip archive.tar.gz restores archive.tar and removes the .gz.

050 — File Display Commands With Hands On

  • cat prints a whole file and can join files. more is page by page, Space for the next page. less scrolls up and down, q quits. head is the first 10 lines, tail the last 10.
  • He rebuilds demo.txt with five echo lines, cats it, then more does not page because the file is shorter than the screen.
  • A for loop appends lines until the file is past 50 lines. Then Space in more advances a page and q quits. less demo.txt scrolls both ways, q quits.
  • head demo.txt shows 10 lines. head -n 3 shows 3. tail shows the last 10. tail -n 2 shows the last two.

051 — Diff & Cmp

  • diff compares text line by line and reports which lines to add, delete, or change. He uses it for source and for patches. Syntax: diff file1 file2.
  • cmp compares byte by byte, stops at the first difference, and reports that byte and line. He uses it for images, PDFs, and compiled programs, where lines do not exist.
  • A .txt file is a diff job. A binary file is a cmp job.

052 — Diff And Cmp Commands Hands On

  • echo hello world > file1.txt and echo hello linux > file2.txt. cat checks both.
  • diff file1.txt file2.txt prints 1c1 (line 1 changed), a left arrow for file1’s line and a right arrow for file2’s line.
  • cmp file1.txt file2.txt says they differ at byte 7 of line 1. He counts: h e l l o space are the same six bytes, then w versus l.

053 — Gzip & Gunzip Hands On

  • echo writes sample.txt. gzip sample.txt creates sample.txt.gz and deletes the original. gunzip sample.txt.gz brings sample.txt back.
  • gzip -k sample.txt keeps the original and also writes the .gz. gzip -v prints the ratio (he sees about 6.5%). gzip -9 is the slowest, smallest setting, 1 through 9.
  • gzip -r newdirectory compresses every file in that folder after he touches a, b, and c inside it.
  • gunzip -k decompresses and keeps the .gz. gunzip -c prints the contents. gunzip -t tests integrity and stays quiet if the file is fine. gunzip -l lists compressed and uncompressed sizes. gunzip -f forces decompression.

054 — Filters - Text Processing Commands

  • He previews the text tools, one lecture each after this.
  • cut pulls columns or fields split by a comma or a tab. awk searches, pulls, and reformats text. grep finds a string.
  • sort orders lines alphabetically, numerically, or in reverse. uniq drops duplicate lines, usually after sort. wc counts lines, words, characters, and bytes.

055 — Text Processing Command Cat

  • Most of the time cat filename just prints the file. He says he will keep using it that way.
  • It can also create a file and merge several files into one stream.
  • Options exist, but he says everyday use is cat plus the file name, with the options left off.

056 — Cat Command Hands On

  • The title says cat. On screen he builds employees.txt with cat > employees.txt and a here-document: id, name, department, salary, comma-separated, for Alice, Bob, Charlie, David, and Eva. Then he runs cut.
  • cut -d, -f1 employees.txt prints the id column. -f2 prints names. -f2,4 prints name and salary.
  • cut -c1-5 prints the first five characters of each line, and the space counts as a character.
  • cut -d, --complement -f1 hides the id column on screen only. cat afterwards still shows the id, so cut does not edit the file. --output-delimiter puts a dash or an arrow between the fields he kept.

057 — Text Processing Command Awk

  • awk splits each line into fields on spaces or tabs. $0 is the whole line, $1 the first field, $2 the second.
  • NF is how many fields are on the line. NR is the current line number.
  • Patterns: awk '{print $1}' data.txt, print $1 and $3, print $3 only on lines that match a word, and print lines where $2 > 100.

awk. A text tool that splits lines into fields and can print, filter, and do arithmetic on them.

058 — Awk Command Hands On

  • He reuses employees.txt. awk -F, '{print $1}' prints ids. -F, means the comma is the separator. $2 prints names. $2,$4 prints name and salary.
  • substr prints only the first five characters of the name field.
  • A small loop from field 2 to NF prints every column except the first. Another print puts an arrow between name and salary.
  • A condition $4 > 50000 prints only Alice, Bob, and Charlie. A header row uses NR==1 for the title and later lines for the data. He says use cut when you only need a column, and awk when you need a test or a calculation.

059 — Text Processing Command Grep

  • grep finds a pattern in a file or in text piped in. He uses it for keywords in logs and in code.
  • Flags: -i ignores case, -v shows lines that do not match, -r walks a directory, -n prints the line number, -c prints only the count.

grep. Search lines for a pattern and print the lines that match.

060 — Grep Command Hands On

  • He writes sample.txt with fruit lines (apple is red, banana is yellow, grapes are green, and so on).
  • grep red sample.txt prints the two lines with “red”. grep is prints every line. grep RED prints nothing. grep -i RED matches anyway.
  • grep -n yellow shows line numbers 2 and 5. grep -c yellow prints 2. grep -w mango matches the whole word only, not a longer word that merely contains those letters.
  • grep -v red prints the lines without “red”. grep -E 'red|green|yellow|sweet' matches any of those words.

061 — Text Processing Command Uniq

  • uniq removes identical lines that are next to each other. It does not hunt duplicates that are scattered, which is why you sort first.
  • Usual pipeline: sort file | uniq.
  • Flags: -c counts repeats, -d prints only lines that were repeated, -u prints lines that appeared once, -i ignores case.

062 — Uniq Command Hands On

  • He writes apple.txt with apple, banana, apple, mango, banana, banana, orange, apple.
  • Plain uniq apple.txt only collapses the two bananas that sit together. The other apples stay, because they are not adjacent.
  • sort apple.txt | uniq gives one of each, in alphabetical order. sort apple.txt | uniq -d prints only apple and banana. uniq -c shows apple 3, banana 2, mango 1, orange 1. uniq -u prints only mango and orange.

063 — Sort Command Hands On

  • fruits.txt has banana, apple, grapes, mango, pineapple, orange, and a second apple. sort fruits.txt is A to Z, apple twice. sort -r is reverse. sort -u keeps one apple.
  • numbers.txt with 45, 30, 7, 80, 900, 3, 56, and a duplicate. sort -n is numeric ascending. sort -nr is largest first. Without -n, sort would order the digits as text.
  • marks.txt is “name score”. sort -k2 -n marks.txt sorts on the second column as a number, lowest score first.

064 — Wc Command Hands On

  • He writes wc.txt with four lines using \n in the echo.
  • Plain wc wc.txt prints three numbers: 4 lines, 12 words, 69 characters (and the same 69 as bytes).
  • wc -l lines only, wc -w words only, wc -m characters, wc -c bytes. wc -L is the longest line, 20 characters on his file.

065 — Truncate Command With Hands On

  • truncate sets a file to an exact size. If the file is missing, it creates it. If the file is longer, it cuts the end. If it is shorter, it pads with empty bytes.
  • He echoes “hello Amazon Linux world” into demo.txt (25 bytes) and checks with ls -lh.
  • truncate -s 10 demo.txt. Size becomes 10. cat shows “hello Amaz” because each letter and space was a byte.
  • truncate -s 40 demo.txt makes the size 40. cat still shows the short text; the extra bytes are blank padding.

066 — File Editing

  • Three ways to add text: the vi editor, echo into a file, or redirecting a command’s output. This lecture is vi. He mentions Pico, Emacs, and Vim, and stays with vi because servers use it.
  • vi opens in command mode. i enters insert mode so typing appears in the file. Escape returns to command mode.
  • Save and quit, from command mode: :w save, :q quit, :wq or ZZ save and quit, :q! quit and drop unsaved edits.
  • Edit keys in command mode: x deletes one character, dd a line, dw a word, yy copies a line, p pastes after the cursor, P pastes before. Move with h left, l right, k up, j down, 0 start of line, $ end of line, gg top of file, G bottom. /word searches forward, ?word backward, n repeats the search.

vi. A terminal text editor. Command mode moves and edits; insert mode types text.

067 — Vi File Editor Hands On

  • mkdir nd, cd nd, vi file. He presses i, the bottom line says INSERT, and he types five lines. Escape leaves insert mode.
  • j and k change lines, h and l move on the line. x deletes the character under the cursor. dd deletes a line. dw deletes a word. u undoes. yy then p copies a line. o opens a new line and drops into insert mode.
  • :w saves. :q leaves. Opening vi file again edits the same file. :q! drops a sixth line he did not save. :wq keeps “this is line six”.
  • /line highlights every “line”. He notes shell scripts are written in vi, then chmod +x so the file is executable and green in ls.

069 — Stream Editor

sed. Stream editor: change text as it streams past, without opening an interactive editor.

071 — Password Aging

  • Password aging forces a user to change a password on a schedule, so a stolen password does not work forever.
  • Minimum age: days you must keep the current password before changing it again.
  • Maximum age: days the password stays valid. After that, the user must change it.
  • Warning period: days of notice before it expires. Inactivity period: days after expiry before the account is locked.

Password aging. A policy that expires passwords after a set number of days and warns the user first.

072 — Password Aging Hands On

  • sudo useradd testuser, then sudo passwd testuser twice to set a practice password.

  • sudo chage -M 90 testuser sets the maximum to 90 days. sudo chage -m 7 testuser sets the minimum to 7. He also sets a warning and an account expiry date with chage -E.
  • chage -l again shows the new dates and the 90-day maximum.

073 — Process - Services Commands (Systemctl, Ps, Top, Kill, Crontab, At)

  • systemctl starts, stops, restarts, enables, disables, and shows status of a service. Older systems used service. Example service: nginx.

  • crontab repeats a job. Five time fields then the command: minute, hour, day of month, month, weekday. Example on the slide: a backup every day at 02:00.
  • at runs a job once. at 10:30, type the command, Ctrl-D to save. atq lists pending jobs.

Daemon. He uses the word for a service systemctl controls, such as nginx, that runs in the background.

074 — Package Management

Package. A bundled piece of software the package manager can install, update, or remove.

107 — History Of Shell

  • Thompson shell, 1971, Ken Thompson at Bell Labs: interactive only, and it introduced the pipe.
  • Bourne shell, 1977, Stephen Bourne: a real language, with if, case, and while. Still the /bin/sh baseline.
  • C shell, 1978, Bill Joy: history and aliases, but a buggy scripting syntax, so Bourne stayed the standard. Korn shell, 1983, David Korn: Bourne scripting plus C-shell conveniences, default on some AIX and Solaris systems.
  • Bash, Brian Fox, GNU “Bourne again shell”: free replacement for sh with Korn and C features, the default on Linux, and what #!/bin/bash means. He also names zsh (Paul Falstad) for heavy customization.

109 — Client Server Relationship

112 — Network Components

  • An IP address is the instance’s address on the network. EC2 has a public IP and a private IP.
  • A subnet mask, written with the IP or as a CIDR such as /20, says how large the network is and which addresses belong together.
  • The gateway is the router address used to reach other networks. On AWS that role is the internet gateway. No gateway route means no internet.
  • DHCP assigns the IP and related settings automatically, which is what AWS does. Static means you type them yourself. He says DHCP is what people use now.
  • The NIC is the virtual network card. Names he expects: eth0, ens5, or enX0 on this instance. The MAC address is the hardware address of that card. ip link show displays it.

Subnet mask. The number that, with the IP, says which network the host belongs to.

NIC. Network interface card, the virtual port the instance uses to send and receive packets.

DHCP. Dynamic Host Configuration Protocol: the server hands out IP and network settings so you do not type them.

120 — Nic

  • A NIC is the hardware, or virtual hardware, that connects the computer to a network. He compares it to a phone SIM. It sends and receives on wired Ethernet or wireless.

  • Steps he previews: load the bonding module, write a bond config under /etc, set the slave NICs, restart the network, and check the bond.

MAC address. The hardware address burned onto a network interface, separate from its IP.

NIC bonding. Combining two or more interfaces into one logical link for speed or failover.

131 — Ftp (File Transfer Protocol)

  • FTP moves files between a client and a server over TCP. Port 21 carries commands. Port 20 carries data.
  • The client connects, then can upload, download, rename, delete, or list files. Two channels: control and data.
  • Active mode: the client tells the server to connect back to a random port. Firewalls often block that. Passive mode: the server offers a high port and the client connects to it. He prefers passive when the client sits behind a firewall. NAT can also break the active translation from an HTTP-style request into the FTP ports.
  • Logins: username and password in plain text (not safe), anonymous with no real credentials, or SFTP and FTP with TLS, which he treats as the secured forms. SSH can carry the file transfer.
  • Commands he lists: ftp server-ip, ls, cd, get download, put upload, mget many files, binary or ascii for the transfer mode, bye or quit. Install client: sudo dnf install -y ftp.

FTP. File Transfer Protocol, a client-server way to move files, with a command port and a data port.

rsync. A copy tool that sends only changed pieces of a file, and can run over SSH.

154 — Ntp

  • He explains why logs, certificates, and scheduled jobs need that shared clock, and the Amazon Linux implementation in the next lecture is chrony, not the old ntpd daemon.

NTP. Network Time Protocol: a way for a computer to set its clock from a trusted time server.

182 — Linux Run Levels

  • A run level is the state the machine is in, and which services are up. systemd still maps the old SysV numbers to targets.
  • 0 is halt: shutdown -h now powers off. 1 is single user, root only, no network, for repair and password resets. 2 is multi-user without the full network setup and is rarely used. 3 is multi-user with networking and no GUI, which is this EC2. 4 is a custom version of 3. 5 is multi-user with a GUI, the desktop case. 6 is reboot.
  • He reads a 0-to-6 table and says servers stay on 3 or 4, while Windows, macOS, GNOME, and KDE sit on 5.

Run level. A numbered system state, from powered off to a full graphical multi-user login.

183 — Booting Process

  • Booting is the machine starting, not only the power button. He walks six steps that he says apply to Linux, Windows, and macOS.
  • Power wakes the CPU, which runs firmware from a fixed place. BIOS is the older firmware. UEFI is the newer one that initializes CPU, RAM, keyboard, and disk controllers in one pass.
  • POST checks that memory, CPU, and disk actually work, and beeps or shows an error if they do not. Then the firmware picks a boot device: SSD, HDD, USB, or, on EC2, the network EBS volume.
  • The bootloader is loaded (BIOS reads the start of the disk, UEFI loads the EFI bootloader). The bootloader loads the kernel. The kernel loads boot files into RAM, subsystems start, and the login screen and services appear.

BIOS. Basic Input/Output System, the older firmware that starts hardware and finds a boot device.

UEFI. Unified Extensible Firmware Interface, the newer firmware that does the same job in one place.

POST. Power-on self-test: the firmware checks that CPU, memory, and disk work.

184 — Steps Of Booting

  • Linux-specific version of the same path. BIOS or UEFI runs POST and finds bootable disks. UEFI loads boot files from the EFI system partition. BIOS loads GRUB stage 1, then later stages.
  • GRUB stage 2 shows a menu so you can pick a kernel or recovery mode, then loads the kernel and initramfs and passes kernel parameters, including the root device.
  • The kernel, once in RAM, sets up memory, detects the CPU, starts drivers, mounts the root file system read-only, and brings up PCI, USB, and storage. It starts process 1, the first user-space process.
  • initramfs is a small temporary file system with disk drivers, RAID, and LVM tools. It loads drivers, decrypts a disk if needed, mounts the real root, then is discarded. systemd (PID 1) mounts file systems, brings up the network, starts installed services, picks the target for the run level, and handles logging. The login prompt is the last step. A GUI loads GDM, KDM, or LightDM instead of a text prompt.

initramfs. A temporary file system used early in boot so the kernel can see the real disks before the root file system is mounted.

GRUB. The bootloader that lets you choose a kernel and then loads it.

185 — Linux Booting Process

  • The shorter modern path. Power, then UEFI checks hardware and loads the bootloader from the EFI system partition.
  • GRUB2 reads its config, loads the kernel and initramfs from /boot, and passes kernel parameters. The kernel sets up memory, CPU, and drivers. initramfs also detects disks, including NVMe and LVM, and the root file system is mounted.
  • systemd becomes PID 1, loads units and the default target, and starts services that are already enabled, such as networking and SSH. Docker or firewalld start only if they were enabled.
  • The login is ready. An SSH login succeeds once the network is up.

186 — Systemd-Analyze Command

  • systemd-analyze is the diagnostic that comes with systemd. It measures boot time, finds slow services, and shows what depends on what.
  • He uses it for boot time, which units delayed startup, the critical path, unit relationships, and a security view of units.
  • Amazon Linux 2023 has systemd 252 or newer, so the command is already there. The actual flags are the next lecture.

187 — Systemd-Analyze Command Hands On

188 — Motd (Message Of The Day)

  • He opens sudo nano /etc/motd only to show where the edit will go.

MOTD. Message of the day: the notice printed right after you log in on a terminal.

190 — Linux Storage

  • Local storage is inside the machine: HDD, SSD, NVMe. It plugs into the motherboard and needs no network.
  • Direct attached storage is cabled to the host (USB, SATA, SAS). The OS sees it as a local disk. He puts EBS in this group: you reach it over the network, but in the data center it is wired to the host.
  • A SAN gives block disks over a dedicated storage network, so a remote disk looks local. NAS shares folders over the LAN. Linux uses NFS, Windows uses SMB, macOS uses AFP. Clients see files, not raw blocks.
  • His table: local and DAS are fast, cheap, and not shared. NAS is structured and medium cost. SAN is fast, shared, and expensive. He picks local or DAS for one machine, NAS for file sharing, and SAN for data-center workloads.

NAS. Network attached storage: a small server on the LAN that shares folders.

SAN. Storage area network: block disks reached over a dedicated storage network.

191 — Disk Partition

  • A partition is a logical slice of a disk. He compares a 1 TB SSD to a house: rooms of different sizes, so one full or broken slice does not take the rest, and two operating systems can share the disk.
  • MBR is the old table: four primary partitions, disks up to 2 TB. An extended partition holds logical partitions, numbered from 5. GPT is the modern table: up to 128 partitions and disks larger than 2 TB. Linux on UEFI uses GPT.
  • A swap partition is disk used as extra memory when RAM is full. Different slices can use different file systems, including XFS and swap, which come later.
  • Commands he previews: df, df -h, df -i, and fdisk -l to list or change MBR and GPT tables. p prints the table inside fdisk. q quits.

Partition. A divided region of one physical disk, used for its own file system or for swap.

192 — Df Command Hands On

  • df prints file systems, 1K-blocks, used, available, use percent, and the mount point. The large one is mounted on /. Others sit on /dev, /run, /boot, and /tmp.
  • df -h turns blocks into G, M, and K. His root volume is about 8 GB and about 20% used.
  • df -i shows inode totals, used, and free. Inodes can run out while byte space is still free.
  • sudo fdisk -l shows the root NVMe disk, 8 GB, disk label type GPT, sector size 512. There is no extra partition table yet. sudo fdisk /dev/nvme0n1 opens the disk and warns that changes stay in memory until you write them.

193 — Lvm

  • LVM sits between the physical disk and the file system so volumes can be resized, moved, or extended while the system runs.
  • A physical volume is a disk or partition (pvcreate). A volume group pools one or more physical volumes (vgcreate). A logical volume is the flexible slice inside the group (lvcreate). You need the group before the logical volume.
  • His command list: lsblk, fdisk to partition, partprobe to reload the table, pvs, vgs, lvs. Example shape: lvcreate -L 10G -n mylv myvg.

LVM. Logical Volume Manager: pool disks, then cut resizable volumes out of the pool.

194 — Adding - Extending Lvm

  • A new EBS disk shows up as something like /dev/xvdf. He partitions it with fdisk, sets the type for LVM, then pvcreate and adds it to the volume group so free space grows.
  • Extend: lvextend -L +5G /dev/myvg/mylv, or lvextend -l +100%FREE to take the rest.
  • Grow the file system after the volume: xfs_growfs on the mount point for XFS. df -h checks the new size.

195 — Lvm Hands On

  • In EC2 Volumes he keeps the 8 GB root disk and creates a 10 GB volume in the same availability zone, then attaches it.
  • lsblk shows the new disk. sudo dnf install -y lvm2 brings pvcreate, vgcreate, lvcreate, and device-mapper. pvcreate --version prints LVM 2.03.

196 — Swap Space

  • Swap is disk used as extra memory. When RAM is full, Linux pages less-used memory out to swap so active processes can stay in RAM. It also allows hibernation. It is much slower than RAM.
  • Swappiness runs from 0 to 100. Near 10 means prefer RAM. 60 or higher means swap is used often. He prefers the low end.
  • Two forms: a swap partition, or a swap file on a file system. His size guide: 4 GB RAM gets about 2 GB swap, 8 GB RAM gets 2 to 4 GB, and larger RAM needs less. Hibernation wants swap at least as big as RAM.
  • Commands he names for the lab: free -h, swapon --show, create a file, chmod, mkswap, swapon, and an fstab line.

Swap. Disk space the kernel uses as overflow memory when RAM is full.

Swappiness. A kernel number from 0 to 100 that says how readily Linux moves memory to swap.

197 — Swap Hands

  • swapon --show lists a 2 GB swap file, priority −2, type file. An empty result would mean swap is off. On this image it is already on.
  • free -h shows RAM used and free, and swap total with 0 used. cat /proc/swaps is the kernel view.
  • He creates a swap file with fallocate -l 2G, hits a busy-file error, retries, then chmod 600 so other users cannot read it. mkswap formats it. swapon turns it on. An fstab line with tee -a makes it permanent. swapoff turns one file off. swapon -a turns on every fstab swap.
  • cat /proc/sys/vm/swappiness is 60. He sets it to 10 for the running system and writes the same line under /etc so sysctl keeps it. To remove a swap file: swapoff, rm -f, then delete the fstab line. At the end free shows the 2 GB swap in use.

198 — Xfs_Info Command

  • xfs_info prints metadata of a mounted XFS file system: inode size, sector size, block size, allocation groups, CRC, directory version, and the log.
  • He reads a sample: metadata (inode size, allocation groups, CRC on means a modern XFS), data (block size and a 25% inode reserve), naming (directory version 2), an internal log, and a real-time section if one exists.
  • History he gives: Silicon Graphics built XFS for IRIX in 1993–94, ported it to Linux around 2000, and xfs_info arrived with the xfsprogs tools. It became a normal Linux tool after kernel 2.6. CRC support is from 2012. Amazon Linux 2023 includes it. The command itself is the next lecture.

XFS. The file system Amazon Linux 2023 uses by default. It can grow while mounted.

199 — Xfs_Info Command Hands On

  • sudo dnf install -y xfsprogs so xfs_info, xfs_repair, and mkfs.xfs exist. xfs_info / prints metadata, data, naming, log, and real-time for the root file system.
  • mkfs.xfs /dev/nvme1n1 fails until he creates a 10 GB volume in the instance’s availability zone and attaches it as sdf. He formats that disk, mkdir /data, and mounts it. mount | grep xfs confirms it.
  • Repair needs the file system unmounted: umount /data, then xfs_repair /dev/nvme1n1. xfs_repair -n scans and changes nothing.
  • xfs_db /dev/nvme1n1 is an interactive metadata debugger. Ctrl-C does not leave it. He types quit. xfs_info stats show allocations. A permanent mount is an fstab line with the path, xfs, defaults, and 0 0, tested with mount -a.

200 — Raid

  • RAID joins physical disks into one logical device for speed, for surviving a disk failure, or both. Linux keeps working if one disk dies, depending on the level. The OS sees one device. The disks stay separate underneath.
  • RAID 0 stripes across at least two disks. All space is usable and reads and writes are fast. One disk failure loses everything. He limits it to temporary data.
  • RAID 1 mirrors at least two disks. The same data is on each disk. Usable space is about half. One disk can die and the other continues. He puts this on a personal machine.
  • RAID 5 needs three disks and spreads data plus parity. It survives one disk failure. Reads are strong and writes are slower than reads. RAID 6 needs four disks and two parity disks, so two can fail. RAID 10 is a mirror plus a stripe, four disks minimum, fast and redundant, which he assigns to busy databases.

RAID. Redundant array of independent disks: several disks acting as one, for speed, a spare copy, or both.

201 — Raid Hands On

  • lsblk shows only the root disk. He creates two 10 GB volumes in the instance’s zone, attaches them, and lsblk shows nvme1n1 and nvme2n1. He says to delete extra volumes later so they are not billed.
  • sudo dnf install -y mdadm. mdadm --zero-superblock on both disks clears old RAID metadata.
  • mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/nvme1n1 /dev/nvme2n1. He answers yes to the metadata warning. cat /proc/mdstat shows both members up ([UU], 2/2). mdadm --detail /dev/md0 prints level, size, and device count.
  • mkfs.xfs /dev/md0, mkdir /raid1, mount /dev/md0 /raid1, df -h. touch /raid1/raidtest.txt and ls prove writes work.
  • Persistence: mdadm --detail --scan | tee /etc/mdadm.conf, then the UUID from blkid /dev/md0 goes into /etc/fstab in vi (i, the UUID line, xfs, defaults, 0 0, Escape, :wq). He terminates the practice instance and deletes the 10 GB volumes.

202 — File System Check

  • A file system check looks for damage from a power loss, a bad shutdown, a failing disk, or a kernel crash.
  • ext2, ext3, and ext4 use fsck, which picks the right checker for the type. fsck -n changes nothing. fsck -y answers yes to fixes. It can also run at boot after a set number of mounts.
  • XFS does not use fsck. It uses xfs_repair on the device path, and the file system should be unmounted. xfs_repair -L clears a stuck log and can drop a little data.
  • His comparison: ext gets an automatic check at boot. XFS is the high-performance one and does not repair itself at boot unless you set that up.

fsck. File system check: the tool that verifies and repairs ext file systems.

203 — Fsck Command Hands On

  • He installs mdadm again, deletes leftover RAID volumes, and attaches two new 10 GB disks in the same zone. lsblk shows them free of /dev/md127.
  • wipefs -a on each NVMe disk clears old signatures. mdadm --create /dev/md0 --level=1 --raid-devices=2 with both disks, answering yes. This time the file system is ext4: mkfs.ext4 /dev/md0, because fsck is for the ext family, not for a bare RAID member.
  • mkdir /data, mount /dev/md0 /data, df -h | grep md0. He unmounts before the check. fsck -n /dev/md0 reports a clean file system. fsck -y would fix errors. There are none. fsck -f forces five passes (inodes, directories, connectivity, reference counts, group summary) and still says clean.
  • mdadm --detail --scan is appended so the array survives reboot. He shows that fsck on /dev/nvme1n1 is the wrong target: that disk is a RAID member, not the file system. Run fsck on the array, unmounted, and wipe old metadata first.

204 — System Backup And Dd Command

  • dd copies raw data block by block. He calls it low level because it talks to the disk, not to files through the network.
  • It can image a whole disk, a partition, or a file system, including the MBR or GPT and the bootloader, even if the file system is damaged. That image is the backup he uses for cloning.
  • Shape: sudo dd if=/dev/nvme0n1 of=/backup/system.img bs=4M status=progress. if is the source, of is the destination, bs is the block size, status=progress prints progress.
  • The copy matches the original, so the image is as large as the disk, there is no incremental backup, and you cannot restore one file out of it. A misplaced image is a copy of the whole system, so he treats it as sensitive.

dd. A command that copies a disk or file as raw blocks, useful for a full image.

205 — Lsblk & Dd Command Hands On

  • lsblk shows the root NVMe disk and the RAID disks from earlier.
  • He mkdir /backup first. Without that directory, dd fails. Then dd if=/dev/nvme0n1 of=/backup/system-full.img bs=4M status=progress. The progress line shows bytes, time, and speed. It runs until the 8 GB disk is copied.
  • ls shows the image. sync flushes it to disk.
  • He says the source must be the disk you mean, the destination directory must exist, and a file system you are imaging should be unmounted when you can do that. The root disk in this demo is the live one, so he treats the command as the lesson and tells you to point of at another disk.

206 — Nfs (Network File System)

  • NFS lets one Linux machine export a directory so another mounts it and uses it like a local folder. His picture: the server has /data, the client mounts it under /mnt, and reads and writes with ordinary ls, cp, and rm.
  • It is built for Unix and Linux. The kernel has the client and server. The package is nfs-utils. Applications do not need to know the files are remote.
  • One server holds the files. Many clients share them. The admin decides who may write, the same idea as permissions and, on AWS, IAM. Uses he names: home directories, application data, backups, and ISO repositories.
  • Versions: NFSv3 is simple and fast. NFSv4 is the one he calls firewall-friendly. 4.1 adds scale. He draws a client crossing the network to an NFS server, and says EBS on EC2 is a related “disk over the network” idea, not the same protocol.

NFS. Network File System: a Linux protocol for sharing a directory so other machines mount it as a folder.

207 — Nfs Hands On

  • sudo dnf install -y nfs-utils is already present on Amazon Linux 2023. systemctl enable --now nfs-server creates the boot symlink.
  • sudo mkdir -p /nfsdata, chown nobody:nobody /nfsdata, chmod -R 755 /nfsdata. ls -ld shows owner nobody.
  • In vi /etc/exports he inserts /nfsdata, a client network, rw, sync, and no_root_squash, then :wq. exportfs -rav exports it. exportfs -v checks. He warns that no_root_squash lets a client root act as root.

208 — Sata & Sas

  • SATA is Serial ATA, Advanced Technology Attachment. It is the storage link on desktops and laptops: how the computer talks to an HDD or SSD. Max speed he quotes is 6 Gbps on SATA 3. One device per port, no second path if the link fails, a shallow command queue. Uses: OS disks, file storage, backup disks, home and office.
  • SAS is Serial Attached SCSI, Small Computer System Interface. He calls it the data-center link: 6, 12, or up to 22.5 Gbps, two ports so one path can fail, a deep command queue, and hot swap. Uses: databases, virtual machines, RAID, and SAN, running all day.
  • His choice: SATA when the budget is tight and the data is not critical. SAS when uptime, databases, and a spare path matter, and the higher price is accepted.

SATA. The common desktop cable and protocol between a computer and a hard drive or SSD.

SAS. The faster server version of that link, with a second path if one connection fails.

209 — Installing Mysql Server And Mariadb On Linux

  • MySQL is an open-source relational database: tables of rows and columns, linked by keys, queried with SQL. Applications in PHP, Python, and Java connect as clients. It is the M in LAMP. Oracle maintains it.
  • He defines ACID. Atomicity: one booking wins if two people take the same seat. Consistency: the row is still there after the transaction. Isolation: a seat held during payment stays unavailable to others for a time-to-live. Durability: a finished transaction survives a crash.
  • MariaDB was built by MySQL’s original developers after the Oracle purchase. Most MySQL applications run on it unchanged. He says it is faster, has more storage engines, and is the one Linux distributions ship. Both install on Amazon Linux 2023. mysql_secure_installation is the lockdown step.

Relational database. Data kept in tables that point at each other, queried with SQL.

LAMP. Linux, Apache, MySQL or MariaDB, and PHP, a common set for hosting a PHP website.

  • How to write a resume aimed at a Linux job, and how to send it.
  • He calls the unit optional if you are not job hunting.
  • One lecture is the resume layout. The others are where to apply and what the job actually is.

220 — Resume Workshop

  • He builds a one-page resume in a document: full name, email, phone with country code, LinkedIn, then the role line “Linux administrator” (or fresher, or system operator).
  • A short summary, four or five lines, not bold: managing servers, building infrastructure, hardening, and installing software. Mention years only if you have them.
  • Skills from this course, as separate lines: operating systems, shell scripting, web servers (nginx, Apache, Squid), virtualization, cloud computing rather than only the word AWS, monitoring and logging, storage, and server security. Bold only the headings.
  • Certifications he names, each with a public verification link: RHCSA, LFCS, and AWS Cloud Practitioner as the easier one. Projects: the Apache or nginx deploy, LAMP, and the hardening and firewall work, with a Google Drive or GitHub link. Education last: school and college, city, year, degree, grades. No photo, because he says automated screens treat a picture as noise.

221 — How To Apply

  • Make accounts on LinkedIn, Indeed, Naukri, and the job site used in your country.
  • For a named company, open its site, scroll to Careers, and apply there. He does this on Red Hat’s jobs page, filters toward a software maintenance role that asks for RHEL, bash, and patches, and says to type the form yourself instead of autofill.
  • IT service firms are the smaller starting point if a Red Hat or AWS role asks for many years.
  • Put projects on Google Drive as well as GitHub, because the person reading the resume may not open a git repo. Certifications and the resume from the workshop are the other two things he wants attached.

222 — Linux Administrator Duties

  • Install and configure RHEL, CentOS, Ubuntu, or Amazon Linux. Set services and kernel parameters. Apply updates and patches.
  • Create, change, and delete users and groups. Set permissions, ownership, and ACLs. Handle sudo, SSH, and PAM.
  • Partitions, LVM, file systems, fstab, disk use, and quotas. IP, DNS, routing, hostnames, NFS, SSH, FTP, and connectivity problems.
  • Start, stop, and watch services with systemctl. Use ps and top. Firewalls, logs, and unexpected logins. Backups, alerts, and uptime. Shell scripts and cron so repeated work is one file. Write the procedure down. Help developers when the fault is the OS, the server, or the hardware.

What he is doing in this unit

  • Typing a resume on screen: contact line, summary, skills taken from the course, certificates, project links, education.
  • Opening a company careers page and showing the apply form.
  • Reading a duty list that matches the commands from earlier units.

After this unit you should be able to

  • Draft a Linux-admin resume that leads with servers, scripting, storage, and security.
  • Point project proof at a Drive folder or a GitHub repo.
  • Find a careers page and send the application without autofill.
  • List the day-to-day work: users, disks, network, services, backups, and scripts.

Unit 13

Exam & Interview Prep

223 — Section 11 Overview

  • Interview and exam questions, sorted easy then medium, on the commands from the course.
  • He says interviewers start with one-line answers, then differences between similar commands.
  • There is no new lab. Each lecture is a list of questions and the short answer he wants.

224 — Easy File & Process Management

  • Files: ls lists, touch makes an empty file, mkdir makes a directory, rm removes a file, rmdir or rm -r removes a directory, cp copies, mv moves or renames, cat prints a file, less pages it, pwd is the present working directory.
  • Processes: ps, ps -ef for every process, top for a live view, kill plus the PID, kill -9 to force it, pidof to find a PID by name.
  • A command ending in & runs in the background. fg brings a job forward. jobs lists background jobs. uptime shows load.

225 — Easy File Permissions & Searching

  • chmod changes mode. chown changes owner. rwx is read, write, execute. 7 is all three, 6 is read and write, 4 is read only, 5 is read and execute. chmod 777 is full access for everyone. chmod 755 is full for the owner and read plus execute for group and others.
  • ls -l shows the bits. umask is the default mode for new files.
  • Search: grep finds text, grep -i ignores case, grep -r walks directories, grep -c counts matches, grep -n prints line numbers. find by name, by type d for directories, or by size. locate is the quick index search.

226 — Easy Compression & Networking

  • Archive: tar -cvf file.tar directory creates, tar -xvf extracts, tar -czvf adds gzip, tar -tvf lists contents. gzip and gunzip for .gz. zip and unzip for .zip. bzip2 is the other compressor.
  • Network: ip addr or ip a for addresses, ping to test a path, ifconfig or ip link for interfaces, netstat for ports, route -n or ip route for the table.
  • wget downloads a URL. scp copies over SSH. hostname prints the name. DNS is the Domain Name System. nslookup tests it. ss shows active connections.

227 — Easy System Info & Shortcuts

  • cat /etc/os-release is the OS version. lscpu is the CPU. free -h is memory. df -h is disk use. du -sh is one directory. uptime is how long the system has been up. uname -r is the kernel. mount lists mounted file systems. lsblk lists disks. who and whoami are the logged-in users.
  • Ctrl-C stops a running command. Ctrl-Z pauses it. fg resumes. Ctrl-L clears the screen. Ctrl-A and Ctrl-E move to the start and end of the line. Ctrl-W deletes a word. Ctrl-R searches history. Ctrl-D leaves the shell. !! repeats the last command.

228 — Medium - File Management

  • cp -r copies a directory tree and is careless with metadata. rsync -a keeps permissions, owner, and times, and sends only what changed.
  • cat dumps the whole file. more and less page it. less can move backward and search.
  • stat shows size, inode, permissions, owner, and the access, modify, and change times. A hard link is another name for the same inode, so deleting one name keeps the data. A soft link stores a path and breaks if the target is removed.
  • du -sh * is the size of each item here, in human units. rm -i asks before each delete. An inode holds metadata and the disk location, not the file name. mv moves or renames one file. rename changes many names by a pattern. head and tail are the first and last ten lines. file reports text, binary, or image from the contents, not the extension.

Inode. The record of a file’s metadata and where its data sits. The name is stored in the directory, not in the inode.

229 — Medium Process Management

  • ps -ef is the Unix column layout. ps aux is the BSD layout. Both list processes.
  • A zombie has finished, but the parent has not collected its exit status, so the row remains. A daemon is a background process that keeps running, such as sshd.
  • nice starts a process at a priority. renice changes one that is already running. A lower nice number is more urgent.
  • kill sends SIGTERM so the process can exit. kill -9 forces it. top shows live CPU and memory. nohup keeps a process after you log out. ss -tlnp or netstat -tlnp shows which process holds a port.
  • A foreground job occupies the terminal. A background job does not. Load average is how many processes wanted CPU over 1, 5, and 15 minutes.

Zombie process. A finished process whose parent has not yet read the exit status, so it still has a row in the process table.

230 — Medium - File Permissions

  • 764 means owner read, write, and execute (7), group read and write (6), others read only (4).
  • chmod +x adds execute and leaves the other bits. chmod 755 replaces the whole mode.
  • The sticky bit on a directory such as /tmp stops users deleting files they do not own. SUID makes a program run as the file’s owner. SGID on a directory makes new files inherit that directory’s group. find with a -perm mode locates SUID files.
  • chown user:group file sets both owner and group. chmod changes a file that exists. umask sets the default for new ones. You need execute permission to enter a directory. 777 lets every account read, change, and run the file.

Sticky bit. A directory flag that lets you delete only the files you own, even if the directory is shared.

231 — Medium - Searching

  • find walks the disk now. locate searches a saved index, so it is faster and can be stale.
  • grep -v prints lines that do not match. grep -E takes more than one pattern. grep -w matches a whole word. xargs turns stdin lines into arguments of the next command.
  • Empty files: find with type file and -empty. Today’s log lines: grep the date against the log. Files changed in the last day: find with -mtime.
  • grep only searches. awk splits lines into fields and can reformat them. cut pulls chosen columns out of a text file.

232 — Medium - Compression

  • tar packs files into one archive and does not compress unless you add z or j. zip archives and compresses in one step.
  • tar -czvf is create, gzip, verbose, and the archive name. --exclude skips a file. bzip2 is slower and usually smaller than gzip.
  • Only logs: tar -czvf logs.tar.gz and the log path. Extract into a chosen directory with -C. zip -r walks a directory, and you can name more than one directory.
  • tar -tvf lists an archive so you can see that it is intact. Compression matters because a smaller file uses less disk and moves faster.

233 — Medium - Networking

  • ping checks that a host answers. traceroute lists each hop the packets take.
  • ss replaces netstat and is faster. Listening ports: ss -lntp. /etc/hosts is the local name-to-address file.
  • TCP is a connection that checks delivery. UDP sends without that check and is quicker. Restart the network stack with systemctl restart NetworkManager when that service is what the machine uses.
  • scp rides on SSH. dig and nslookup both test DNS. A port is the numbered door on a host, such as 443 for HTTPS.

234 — Medium - System Information

  • df is space per mounted file system. du is space per directory.
  • uname -a is kernel name, version, and architecture. top or htop is memory per live process. /proc is a virtual file system of process and kernel data. lsblk shows disk types. free -m is memory in megabytes. lscpu is the CPU, including cores. There is no space in lscpu.
  • Swap is disk used as extra memory. systemd-analyze prints boot time. He says monitoring matters because it shows a failing service and an unexpected login while you can still act.

235 — Medium - Shortcuts

  • Ctrl-C stops a process. Ctrl-Z pauses it. Ctrl-R searches history. Ctrl-D logs out or sends end-of-file.
  • Tab completes a command or a path. Ctrl-U clears the line you are typing. Ctrl-D, in that editing sense, deletes the character in front of the cursor. Ctrl plus an arrow jumps a word.
  • sudo !! runs the previous command as root. He says the reason for shortcuts is speed: fewer keystrokes on work you repeat all day.

What he is doing in this unit

  • Reading question lists, easy then medium, and answering with the command or the one difference that matters.
  • Covering files, processes, permissions, search, compression, networking, system info, and keyboard shortcuts.
  • No new instance and no new package. The answers point back at commands already used.

After this unit you should be able to

  • Answer the short file, process, permission, and network questions with the command, not a paragraph.
  • Explain hard link versus soft link, zombie versus daemon, and df versus du.
  • Give the three-digit meaning of modes such as 755 and 764, and say why 777 is a bad default.
  • Use Ctrl-C, Ctrl-Z, Ctrl-R, and sudo !! without looking them up.
