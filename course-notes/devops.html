02 — Introduction to DevOps

002 — Introduction

  • DevOps joins development and operations: host, deploy, monitor, maintain, and scale an app after the code is written.
  • He sketches the software lifecycle with feedback loops, and names waterfall and agile as two ways teams plan that work.
  • CI means take local changes into the source repo, run tests, and package the result. CD means deliver that package onto the server.
  • A container packages the runtime, libraries, code, and files so the same environment runs on a laptop or a server. His example is Python plus pandas plus a CSV.
  • The course path he announces: Linux and Bash, Python, Flask, Git, Docker, AWS, Kubernetes, Terraform, then CI/CD. He also names Ansible, Chef, and Nginx as config and web tools you will meet later.
  • Cloud providers he will use: AWS as the main one, Azure for data and streaming, GCP for Kubernetes and build pipelines. He also mentions Linode, OpenShift, and DigitalOcean.

DevOps. The practice of one person or team owning both the code and the systems that run it.

Bash. The Bourne Again Shell, the command line you type into on Linux. Other shells exist, such as zsh and fish.

03 — Cloud computing

003 — Introduction to Cloud

  • Cloud means the machines live in someone else’s data centre, not under your desk.
  • He splits clouds into private (only your company), public (AWS, Azure, GCP), and hybrid (both).
  • He draws the service stack. Use the standard meanings, which he restates correctly in the AWS unit: IaaS is hardware you manage (EC2), PaaS is a platform you drop code onto (Elastic Beanstalk), SaaS is finished software you just open (YouTube, Sheets, Excel).
  • He names GitHub as a platform that hosts Git, which is the PaaS idea: you bring the repo, they run the service.
  • No console clicks in this lecture. It is the vocabulary for the AWS unit.

IaaS. The provider gives CPU, memory, and disk. You install the operating system and the app.

PaaS. The provider gives a runtime. You give it code and it runs it.

SaaS. The provider gives a finished application you use in a browser.

04 — Linux basics

Ubuntu is the distro he recommends. Open a terminal with Ctrl+Alt+T. He keeps a command gist called Linux Commands Tutorial.

004 — Basics of Linux Part-1

  • Linux is an operating system, like Windows or macOS. The kernel talks to the hardware. A distro is a full system built on that kernel.
  • He names Ubuntu for daily use, Kali for security, Debian as Ubuntu’s parent, CentOS for servers, Alpine as a tiny image, plus Arch and Fedora. Linux is mostly C, GPL-2, started by Linus Torvalds, who also made Git.
  • File tree he points at: /bin for programs (whereis ls shows /bin/ls), /etc for config, /home for users, /var for logs, /mnt for disks you mount later.
  • Navigation: pwd, ls, ls -a, ls -l, ls -al, cd, cd .., cd - for the previous folder, Tab to complete, up and down for history, clear.
  • Files: mkdir (no spaces; use - or _), touch, mv to move or rename, cp, rm, rm -rf which deletes with no recycle bin, ln -s for a symlink.
  • Reading: cat for files, echo, man then q to quit. Identity: uname, uname -a, whoami. Paste in the terminal is Ctrl+Shift+V.

Distribution. A packaged Linux system: kernel plus the tools and installer a vendor chose.

Root user. The administrator. On root, sudo is unnecessary and sometimes missing.

005 — Basics of Linux Part-2

  • Archives: tar -cvf archive.tar folder to pack, tar -xvf archive.tar to unpack. zip and unzip when the other machine is not Linux.
  • Search and slices: grep on a pipe, grep -n for line numbers, head, tail, head -n 5, tail -n 5.
  • Environment: export NAME=value lasts for this shell only. echo $HOME and printenv show what is set.
  • Processes and disk: ps, ps aux, ps | grep, kill PID, service --status-all (+ running, - stopped), df, df -h, top.
  • Permissions: chmod +x file makes it runnable. chmod 777 is read-write-execute for everyone. He says not to use 777 on real files. Letters are rwx for user, group, and others.
  • Network and packages: ifconfig (docker0, wlan, lo), curl URL prints the body, wget URL saves a file. Ubuntu uses apt: sudo apt update, sudo apt upgrade, sudo apt install cowsay, sudo apt remove cowsay. CentOS uses yum or rpm, Alpine uses apk, Arch uses pacman. Snap is Ubuntu’s own store.
  • He also installs cmatrix, neofetch, and mentions btop. Aliases such as alias c='clear' die when the shell closes. SSH, services, and ufw wait until Nginx and AWS.

What he is doing in this unit

Walking the filesystem, creating and deleting files, packing a tar, grepping output, installing a joke package with apt, and setting a one-session alias.

After this unit you should be able to

  • Move around with pwd, ls -al, and cd, and create a folder whose name has no spaces.
  • Copy, move, and remove files, including a symlink with ln -s.
  • Read a file with cat, search it with grep, and look up a command with man.
  • Update Ubuntu and install a package with sudo apt update and sudo apt install.
  • Check disk with df -h and stop a process with kill after finding it in ps aux.

05 — Scripting (Python and Bash)

There is no separate Bash lecture. Bash is the shell from unit 04. This unit is Python 3. He uses 3.10, wants 3.8 or newer, and writes files in VS Code with auto-save on.

006 — Basics of Python Part-1

  • Python is high-level, interpreted, and dynamically typed. Python 2 is retired. Install from python.org, or use Miniconda or Anaconda if you want a package manager. Run a file with python3 file.py.
  • He creates first.py with print("Hello world"), then my_data_types.py and basic_objects.py.
  • Types he types: str in quotes, int, float, bool as True or False. A variable is a = 10. Math is + - * /.
  • Strings: .capitalize() and .upper(). A comment is #. \n is a newline and \t is a tab.
  • A list [] is mutable and starts at index 0. A slice a[1:5] stops before 5. He uses append and del. A tuple () cannot change. A set {} keeps unique values. A dict is {key: value} with a colon and commas. Delete with del dict[key] and add with dict[k] = v.

Interpreter. A program that runs your source line by line, instead of compiling it to a binary first.

007 — Basics of Python Part-2

  • He writes if_statements.py. Branches are if, elif, and else. Comparisons are ==, !=, >, <, >=, <=. Indentation is the block.
  • input() always returns a string. Wrap it in int() when you need a number.
  • for_loops.py: for i in some_list and for i in range(10), which is 0 through 9. list(range(10)) makes that into a list.
  • Modules: import datetime then datetime.datetime.now(), or from datetime import datetime, or from math import sqrt.
  • His own module is a folder basic/ with fruits.py holding apples = 10, bananas = 20, oranges = 30. The caller does from basic import fruits.
  • Files: modes r w a r+ w+ rb. He opens data.txt, reads with read, readline, or readlines, writes, and closes. Errors go in try / except in trial_error.py.

008 — Basics of Python Part-3

  • A function is def name(): with an indented body, called with (). It can return a value, take arguments, and sit inside another function.
  • Functions are values. You can assign one to a name without calling it, then call the new name later.
  • Packages come from PyPI. He runs pip3 install Faker, then from faker import Faker and calls fake.name(), .city(), .country(), and .address() in faker_tutorial.py.
  • A while loop in while_tutorials.py: start i at 0, print while i < 10, then i = i + 1 or i = i + 2.
  • He compares package tools: pip for Python, npm for Node, modules for Go, Gradle or Maven for Java.
  • He defines a program as one file that runs, and software as many programs working together. Keywords are reserved words. Identifiers are the names you invent.

PyPI. The public index pip downloads packages from.

What he is doing in this unit

Creating small .py files in VS Code and running each one with python3. He installs Faker, builds a tiny package folder, and reads and writes data.txt.

After this unit you should be able to

  • Run a script with python3 file.py and install a library with pip3 install.
  • Use lists, tuples, sets, and dicts, and slice a list without including the end index.
  • Write if / elif / else and both for and while loops with correct indentation.
  • Turn input() into an int before doing math.
  • Import a standard module and your own module from a folder.
  • Open a file, read or append, close it, and catch a failure with try / except.
  • Write a function that takes arguments and returns a value.

06 — REST APIs using Flask and MongoDB

009 — Flask Framework Part-1

  • A web framework gives you routes and request handling. A web server is the process that listens on a port. Django is batteries-included. Flask is small. He also names web2py, Bottle, and CherryPy. Express is the Node equivalent.
  • REST is a client asking and a server answering. A URL has a protocol (http or https), host and port, a path, and an optional query string. JSON looks like a Python dict.
  • GET asks for data, often in the query string. POST sends a body. He also names PUT, PATCH, and DELETE. Status 200 is success, 404 is missing, 500 is the server’s fault.
  • In Postman he calls https://reqres.in/api/users and the same URL with ?page=2, saved in a collection named DevOps course.
  • Install with pip install Flask. Folder Flask tutorial, file app.py: app = Flask(__name__), @app.route("/"), and app.run(debug=True) under if __name__ == "__main__":. Debug reloads on save.
  • He adds /about and /second, a path parameter /api/<name>, and /add/<a>/<b> that converts both parts with int() and returns a dict, not a bare int. Query values come from request.args.get("name").
  • Templates live in templates/index.html. render_template("index.html", day_of_week=...) fills Jinja {{ day_of_week }}. He uses the weekday and strftime for a /time page. A form uses method="POST" and action="/submit". Read it with request.form.get("name"), not request.args.

JSON. A text format for objects and lists. In Python you treat it like a dict.

Jinja. The template language Flask uses so HTML can print Python values.

010 — Flask Framework Part-2

  • Relational databases (MySQL, Postgres, Oracle) store tables. Document databases (MongoDB, CouchDB) store JSON documents. A group of documents is a collection. Collections make a database. He also names Neo4j for graphs, Redis for key-value cache, and Google Drive or S3 for blobs.
  • On cloud.mongodb.com he creates a free Atlas cluster in Mumbai named tram. Database user dummy with password 1234 and the Atlas admin role, not a temporary user. Network access is 0.0.0.0/0. He says that is wide open. A tighter rule uses your public IP from a site such as ifconfig.me.
  • Connect → Drivers → Python. Copy the URI, replace <password>. requirements.txt lists flask, pymongo, dnspython, and python-dotenv. .env holds MONGO_URI. Load it with load_dotenv() and os.getenv.
  • client["test"] is the database and db["flask_tutorial"] is the collection. insert_one needs a dict. Do not return the ObjectId in JSON. Return a plain success string. find() is a cursor. Turn it into a list, delete each _id, and wrap it as {"data": ...}.
  • He splits a monolith into frontend/ and backend/. Backend listens on port 9000 and host 0.0.0.0. Frontend listens on 8000 and posts JSON with the requests package to backend_url + "/submit". The backend reads request.json, not request.form. A GET /view uses jsonify. The browser button is a link to /get_data.
  • Install with pip install -r requirements.txt and start with python3 app.py.

Microservice. One small app that does one job and talks to the others over HTTP. A monolith is all of that in one process.

Building app.py and templates/index.html, calling a public API in Postman, creating an Atlas cluster, writing .env and requirements.txt, inserting a signup form into Mongo, then splitting the app into two Flask processes on ports 8000 and 9000.

After this unit you should be able to

  • Start a Flask app with debug on and add a route that returns text or a dict.
  • Read a query string with request.args and a form with request.form.
  • Render a Jinja template and print a variable with {{ }}.
  • Create a free Atlas user, open the network, and connect with pymongo from a .env URI.

07 — Version control — Git

011 — Introduction to Git

  • Version control keeps every saved snapshot of a project. Git is the tool. GitHub is Microsoft’s host for Git repos. GitLab and Bitbucket are other hosts. GitLab is the one he associates with CI and security scans.
  • Linus Torvalds built Git after an older, slower system. Git is not the same thing as GitHub.
  • Install: Linux often already has it, otherwise sudo apt install git. Mac is brew install git. Windows uses the installer plus Git Bash. Check with git --version.
  • He creates a folder (he calls it Athena in later videos) and an index.html that says Git tutorial. This lecture is the vocabulary before the commands.

Git. The program on your machine that records commits.

GitHub. A website that stores Git repositories so other people can clone them.

012 — Git Basics

  • Inside the project folder he runs git init. The first branch is master. He notes that many hosts now call that branch main.
  • VS Code’s source control marks a new file with a green U (untracked) and a changed file with a brown M (modified).
  • git add file or git add . stages work. git status shows what is staged. git restore --staged file takes a file back out of the stage.
  • The hidden .git folder is the database. He says never edit it by hand.
  • He sets short aliases he will reuse: ga for add, and log aliases that expand to git log --stat and git log --oneline --decorate --graph --all.

013 — Commits

  • git commit -m "message" saves the staged snapshot. git log shows author, email, date, and the hash.
  • HEAD is the latest commit. git diff hash shows what changed since that commit.
  • You cannot delete a commit in the middle of history. You can only move HEAD backwards. git reset --hard hash throws away every commit after that hash. He treats that as destructive.
  • He edits index.html, then adds hello.txt and data.html, committing after each change so the log has several entries.

Commit. A saved snapshot with a message, an author, and a hash.

HEAD. The name Git uses for the commit you are standing on.

014 — GitHub

  • He generates a key with ssh-keygen using his GitHub email, then cat ~/.ssh/id_rsa.pub and pastes it into GitHub → Settings → SSH and GPG keys as an authentication key.
  • He creates a private repo named Athena. git remote add origin git@github.com:.../athena.git, then git remote -v.
  • The first push is git push -u origin master (or --set-upstream). Later pushes are just git push.
  • GitHub Pages: Settings → Pages → deploy from branch master at the root. The repo needs an index.html. A private repo can take a while to publish.
  • He writes README.md. # is a big heading, ## is smaller, and an image is ![alt](url). He mentions readme.so and VS Code’s Ctrl+Shift+V preview. He also saves the keygen steps in newkey.txt and a command recap in recap.txt.

015 — Remotes GitLab

  • One local repo can have two remotes. origin stays GitHub. He adds GitLab with git remote add glorigin git@gitlab.com:....
  • The same public key is pasted into GitLab’s SSH keys page. The private key stays on the laptop.
  • git push glorigin master sends the same commits to GitLab without changing GitHub.
  • He uses this to show that Git is local and the host is just a remote URL.

Remote. A nickname for a URL where you push and pull commits.

016 — Branching

  • git branch -a lists branches. He describes remotes in one colour and the current local branch with a star.
  • git branch feat1 creates a branch. git switch feat1 moves onto it. The older form is git checkout -b feat2 and git checkout feat1.
  • The first push of a new branch needs git push -u origin feat1.
  • If he edits a file on the GitHub website, the laptop is behind until git pull.
  • To merge, stand on the target: git switch master, then git merge feat1, then git push.
  • He mentions rebase as replaying commits in a straight line, and says day-to-day work uses merge. A merge commit is the join point.

Branch. A movable label for a line of commits, so two features can be saved separately.

017 — Pull Requests

  • He pushes feat3 and opens a pull request on GitHub from feat3 into master. GitLab calls the same thing a merge request.
  • When both sides edited the same lines, GitHub shows a conflict. He keeps one side or both, marks the file resolved, and merges in the browser.
  • After the website merge, the laptop still has the old master until git pull.
  • The rule he repeats: do the review on the host, then update the laptop. Do not merge a conflicted file without reading both sides.

Pull request. A request for someone to merge your branch into another branch after they have looked at the diff.

018 — Forking

  • A fork is your copy of someone else’s public repo. He forks a repo he calls Minerva, clones the fork, commits, and pushes to his own GitHub.
  • Contribute → Open pull request sends the commits back to the original repo. Only the upstream owner can merge that request.
  • Later upstream commits are pulled with the Sync fork button, then a pull on the laptop.
  • He points at the Linux kernel as the real-world version of this flow.

Fork. A remote copy of a repo under your account, so you can push without write access to the original.

019 — Stashing

  • If you have unfinished edits and need to switch branches, git stash shelves them. git stash list shows the shelf.
  • He switches branch, does other work, switches back, then git stash apply. A numbered stash is stash@{n}.
  • git stash drop removes one entry. git stash clear removes all of them. Daily use is git stash and git stash pop, which applies and drops in one step.
  • Recap he writes down: git init, git remote add origin URL, change files, git add, git commit, git push. He mentions GitKraken when you want a picture of the graph.

Stash. A temporary shelf for uncommitted edits so the working tree can change branch.

What he is doing in this unit

Initializing a repo, committing HTML files, making an SSH key, pushing to a private GitHub repo and a second GitLab remote, publishing Pages, branching feat1 through feat3, merging, opening a pull request, forking Minerva, and stashing a half-done edit.

After this unit you should be able to

  • Start a repo and make a commit with a message.
  • Add an SSH key and push with git push -u origin master.
  • Create a branch, switch to it, and merge it back.
  • Open a pull request and pull the result after it is merged.
  • Fork a public repo and send changes upstream without write access.
  • Stash work, switch branch, and pop the stash afterwards.
  • Add a second remote and push the same commits to GitLab.

08 — Docker

020 — Introduction to Docker

  • Docker packages an app so it stops depending on whatever happens to be installed on one laptop.
  • An image is the packed layers. A container is a running image.
  • A virtual machine stacks hardware, a host OS, a hypervisor such as VMware, then a full guest OS and the app. That is gigabytes and includes a desktop.
  • Docker uses the host kernel. There is no guest OS. The result is a command line only, usually megabytes rather than gigabytes.
  • He will install the engine, run images from Docker Hub, write a Dockerfile, compose the Aries app, and push to a registry. Private registries (ECR, GCR, ACR) come in the AWS unit. Heroku’s free tier is gone, so the cloud run waits for ECS.

Image. A read-only package of filesystem layers.

Container. A running instance of an image.

021 — Installation

  • On Ubuntu: sudo apt install docker.io.
  • So you do not need sudo every time: sudo groupadd docker, sudo usermod -aG docker $USER, then newgrp docker.
  • Check with docker version and docker run hello-world.
  • He signs in at hub.docker.com. Image names look like username/repo.

022 — Basic Commands

  • docker pull ubuntu, docker images, docker run ubuntu. A plain Ubuntu container exits at once because it has nothing to do.
  • docker ps is running containers. docker ps -a includes exited ones.
  • docker run -it ubuntu gives a shell as root. Inside, apt works without sudo. He runs apt update && apt install vim and edits a file.
  • Leave the shell first, then docker stop id and later docker start id.
  • Alpine uses apk update and apk add vim, not apt. Kali is docker pull kalilinux/kali-rolling and still uses apt.

023 — Advanced Commands

  • docker run nginx pulls the image if it is missing. Publish a port with -p host:container, so -p 8000:80 maps your port 8000 to Nginx’s port 80. He swaps the order once on screen. The left number is always the host.
  • curl against the host port shows the welcome page. docker logs id prints what the container wrote. docker run -d keeps it in the background.
  • docker exec -it id bash opens a shell in a running container. Inside, curl localhost:80 works. localhost:8000 does not, because 8000 exists only on the host.
  • docker inspect id shows the container IP and the port bindings. He defers user-defined networks to Compose.

024 — Docker files

  • A Dockerfile starts with FROM python, then he switches to FROM python:3.8-alpine and the image drops from about 932 MB to about 48 MB. slim-buster is around 112 MB.
  • He COPYs app.py, sets a WORKDIR, and ends with CMD or ENTRYPOINT.
  • docker build -t python-hello-world . then docker run python-hello-world. Tags such as :v2 mark a later build.
  • A Node example is FROM node:16-alpine, ENTRYPOINT ["node"], CMD ["app.js"], built as nodejs-hello.
  • RUN echo hi and RUN touch a.txt happen at build time, not at run time.

Dockerfile. A text recipe that builds an image, one instruction per layer.

025 — Image Handling

  • Old builds leave dangling images. docker image prune deletes them.
  • docker rmi id fails while a container still points at the image.
  • Remove every stopped container with docker rm $(docker ps -aq) or docker ps -aq | xargs docker rm, then remove the image.
  • He deletes containers and images before a rebuild so the next docker build is not confused with a stale tag.

026 — Building Microservices

  • The Aries app is two services. Backend is Flask in app.py, listening on port 8000 and host 0.0.0.0. If the host stays 127.0.0.1, the published port stays closed.
  • /api reads names.txt through business.py and get_data, then jsonifys {"data": ...}. requirements.txt is just flask.
  • Frontend is Express: npm init -y, npm install express ejs node-fetch, app.js, then an EJS page that fetches process.env.BACKEND_URL or a hardcoded localhost:8000/api.
  • .dockerignore lists node_modules. Builds: docker build -t aries-backend -f Dockerfile-backend . and a frontend image from node:16-alpine with WORKDIR /app, npm install, ENTRYPOINT npm, and CMD start.
  • He maps host 4000 to container 8000 for the backend. The frontend container cannot reach the backend through localhost until they share a network. That is the next lecture.

027 — Docker Compose

  • Install the Compose plugin and check docker-compose --version.
  • docker-compose.yaml has a version and two services. Backend builds from ./backend, sets hostname: backend-host, and publishes 8000:8000. Frontend builds from ./frontend, sets BACKEND_URL to http://backend-host..., and uses depends_on plus links.
  • Both services join a network named aries-network. Volumes are mentioned and then postponed to Kubernetes.
  • docker-compose up builds and starts both. The frontend reaches the backend by the hostname, not by localhost.
  • He runs git init, adds a .gitignore, and pushes a public repo he describes as the Aries app, with a README titled Docker tutorial.

Compose. A YAML file that starts several containers, with a shared network and a start order.

028 — Push Registry

  • docker login and later docker logout.
  • He tags the local image as username/aries-backend:latest and runs docker push. The registry stores a compressed copy. A pull on another machine gets the same image.
  • Public Docker Hub is fine for this demo. Real apps go to a private registry: AWS ECR, Google GCR, or Azure ACR.
  • He removes local images and containers before rebuilding so the tag he pushes is the one he just built.

What he is doing in this unit

Installing Docker, joining the docker group, running Ubuntu, Alpine, Kali, and Nginx, writing Dockerfiles, building the Aries backend and frontend, starting them with Compose, and pushing the backend image to Docker Hub.

After this unit you should be able to

  • Install Docker and run a container without sudo.
  • Pull an image, run it interactively, and map a host port with -p host:container.
  • Read logs, exec into a container, and inspect its IP.
  • Write a Dockerfile with FROM, WORKDIR, COPY, RUN, and CMD, and prefer a small Alpine or slim base.
  • Build the Aries API so it binds 0.0.0.0, and reach it from a second container by hostname.
  • Start both services with docker-compose up and push a tagged image after docker login.

09 — AWS

Region is ap-south-1 unless a screen says otherwise. The IAM user is “course user”. Do the labs as that user, not as root. Delete stacks, clusters, and instances when the lecture ends so they do not keep billing.

029 — Introduction to AWS

  • AWS is a large set of services. He says it is the biggest public cloud. The console is the website. The CLI he wants is version 2, not version 1.
  • Install: Windows MSI, Mac brew install awscli, Linux the three official install commands. Check aws --version.

  • He restates SaaS, then PaaS, then IaaS in the correct order. A VPC is an isolated network. Each region already has a default VPC and subnets. He skips custom CIDR and peering.

030 — IAM S3

  • The root account is the email that owns the bill. Day-to-day work uses an IAM user. He creates “course user” with console access, a custom password, the AdministratorAccess policy, and a tag course.

10 — Kubernetes

He starts on Minikube, then moves the Fenrir demo to a Google Kubernetes Engine cluster. Docker must already be installed. K8S is the short name: K, eight letters, S.

051 — Introduction to Kubernetes

  • Kubernetes is a container orchestration tool. It creates, updates, scales, and deletes containers for you. You need the Docker unit first.
  • One company ends up with many microservices: a frontend, a backend, and a database, repeated per product. Compose can hold a few of them. He has seen clusters with more than a thousand.
  • Problems he lists: nobody can remember the map, it is hard to copy into another environment, disks disappear when a container dies, and a crash needs a restart and a way to share traffic.
  • Features he writes down: deploy, manage, scale, update, roll back, health checks, logs, exec, port forwarding, labels, security, and load balancing.
  • Google built it for their own containers and open-sourced it. The community now contributes. The next lecture names the objects you will create.

Orchestration. Software that keeps the right number of containers running and sends traffic to them.

052 — Main Components

  • A node is a machine, virtual or physical, with CPU, memory, and a little disk. An EC2 instance can be a node.
  • A pod is the smallest thing you run. It is usually one container. Extra containers in the same pod are sidecars.
  • A deployment is a pod template plus a replica count. You create the deployment. Kubernetes creates and replaces the pods. Restarting the deployment deletes the pods and makes new ones.
  • A service is how you reach a deployment. It load-balances across the pods. An internal service is only for the cluster. An external one is reachable from outside.
  • An ingress is one entry point in front of many services, the same idea as Nginx on EC2. It can also terminate TLS so each service does not.
  • A StatefulSet is a deployment whose data must survive a restart. A function that squares a number is stateless. A database is stateful.
  • A ConfigMap holds settings such as BACKEND_URL. A Secret is the same idea for private data, stored base64-encoded, such as a TLS key. A PersistentVolume asks the cluster for disk, for example 100 GB. A PersistentVolumeClaim takes part of that disk for one app.
  • He names extras he will not drill yet: ReplicaSet, StorageClass, DaemonSet, Job, CronJob, Namespace, and Custom Resource Definition.

Pod. One running container, or a few containers that always share a network and a disk.

Deployment. The object that keeps N copies of a pod template running.

053 — K8s Architechture

  • A cluster has at least one control-plane node (he says master) and zero or more workers. Two control-plane nodes is the safer picture he draws.
  • A worker runs kubelet, kube-proxy, and a container runtime. The runtime in this course is Docker. Kubelet asks the node for CPU and memory when Docker starts a container. Kube-proxy assigns cluster IPs and does the in-cluster load balancing. He also mentions cluster DNS.
  • The control plane has those same three pieces plus an API server, a scheduler, a controller manager, and etcd.
  • kubectl talks only to the API server. The scheduler decides that something must be created. The controller manager picks a node that has room and tells that node’s kubelet. etcd stores the cluster’s desired state. He says never edit etcd yourself. You cannot usefully do it. Kubernetes owns it.
  • On EKS or GKE the cloud builds the control plane. He says a DevOps engineer must know pods, deployments, and services first, and the control-plane pieces second.

etcd. The cluster’s database. It stores what should exist and what currently exists.

kubectl. The command-line client. It sends your requests to the API server.

054 — MiniKube Kubectl

  • Minikube runs a Kubernetes cluster on your laptop, inside Docker. He warns that a small laptop will struggle. His machine has 32 GB of RAM. Kind is the lighter alternative. Kind does not include the dashboard or ingress by default.
  • He installs the Minikube binary from the docs, not the deb or rpm, then checks minikube is on the path. Docker must already answer docker version.
  • minikube start --nodes 2 -p altair makes a two-node cluster (one control plane, one worker) named Altair. The first start downloads a few hundred megabytes.
  • He then notices kubectl is missing, installs it from the Kubernetes docs, and checks the version with kubectl version.
  • The same kubectl binary can point at more than one cluster. The context decides which one receives the next command.

055 — Dashboard

  • The dashboard is a web UI for what is running and how much CPU and memory it uses. EKS and GKE have this in their consoles. Minikube does not, until you open it.
  • On a cluster without Minikube’s addon, the docs say kubectl apply -f the recommended dashboard manifest, then kubectl proxy, then open the printed URL. apply -f means “make the cluster match this file”.
  • On Minikube the short command is minikube dashboard. His named profile Altair is in a bad state, so he stops those containers, runs minikube start --nodes 2 without a custom name, and opens the dashboard again.
  • He checks minikube status and kubectl get all. A node in this demo is using a lot of RAM, which is why he told small laptops to skip Minikube.
  • Namespaces are separate folders for objects. A fresh cluster has default, kube-node-lease, kube-public, kube-system, and, on Minikube, kubernetes-dashboard. kube-system holds etcd, the scheduler, the API server, and kube-proxy. He says never change those. Old leftover namespaces get kubectl delete namespace NAME.
  • docker system prune and a volumes prune free several gigabytes of old Minikube data. He restarts the cluster afterwards so the dashboard is empty in default.

Namespace. A folder inside one cluster. Most apps are created inside a namespace. Nodes and persistent volumes are not.

064 — Intro to Terraform

  • Terraform is infrastructure as code, made by HashiCorp. You describe cloud resources in files and create or delete them with a command. He compares it to CloudFormation, with the difference that one configuration can talk to AWS, GCP, Azure, and Kubernetes.
  • His example architecture is RDS MySQL, an EC2 instance, and an S3 bucket, created together and removed together with terraform destroy. He likens that packaging to Helm, but for infrastructure.
  • He reuses the IAM user “course user” and checks that an access key id and a secret access key exist. He copies both into notes.txt inside a new folder terraform tutorial. Those keys must not be committed later.
  • Install from the Terraform site. On Ubuntu he prefers snap. terraform --version shows 1.3.9 in the video. He sets alias tf=terraform for the rest of the unit.
  • A configuration has a provider (where and with which credentials), resources (what to create), and helpers such as variables, outputs, and modules. A resource without its provider cannot be created.

Infrastructure as code. The servers, buckets, and networks are written in files, so they can be reviewed and recreated.

067 — Terraform Commands

  • terraform plan prints what would change and changes nothing. terraform plan -out=s3.plan saves that plan. terraform apply s3.plan runs the saved plan even if you edited the .tf files afterwards.
  • terraform validate only checks syntax. A valid-looking typo can still pass. A missing required argument fails it. terraform apply without a plan file asks for yes unless you pass -auto-approve. terraform destroy deletes everything in the state.
  • An input variable has a type and a default. He references it in the bucket tag. A file such as terraform.tfvars with number = 300 overrides the default, which the next plan shows.
  • An output, usually in outputs.tf, prints a value after apply. He outputs the bucket id, then switches the attribute to the hosted zone id and applies again to see the new value.
  • .gitignore ignores .terraform/, *.tfstate, state backups, *.tfvars (the secrets), and plan files. He deletes the .plan file, git init, commits, creates a public repo, and git push -u origin. Someone else clones it, fills in variables, and runs init and apply.

12 — Continuous integration — Jenkins, CircleCI, GitHub Actions

068 — Introduction to CI-CD

  • Developers push to one Git repo. Users only talk to the running server. CI/CD is the automatic path between those two. CI packages the code (for example a Docker build and pip install). CD puts that package on the server. He uses “continuous delivery” for the second half.
  • Without a pipeline, a person has to pull, build, and restart by hand. A pipeline does that on every push. He wants a small project’s pipeline to finish within a few minutes.
  • He invents three types for the rest of the unit. Self-hosted means you run the CI server and pay for its CPU and disk. Jenkins is the example. VCS-embedded means the Git host includes CI. GitHub Actions is the example. GitLab and Bitbucket do the same. External means a company runs the workers for you. CircleCI is the example.
  • Self-hosted keeps working if GitHub is down, as long as your Git remote is reachable. You have to patch the CI server yourself. The other two do not need a server, and they stop if that vendor stops.

069 — Introduction to Jenkins

  • He installs Jenkins on a Google Compute Engine VM so the AWS unit is not repeated. Ubuntu, not Debian. He adds the Jenkins apt key and repository, then sudo apt install jenkins. systemctl status jenkins shows active.
  • The VM has a network tag jenkins. A firewall rule allows TCP 8080 (the UI) and TCP 9000 (the demo app later) from 0.0.0.0/0, targeted at that tag. http://VM_IP:8080 opens the setup page.
  • The one-time password is the secret printed on that page, also stored on the VM for the initial admin. He chooses Install suggested plugins, then creates the admin user. He uses a short password in the video. Use a real one on any VM you leave running.
  • He notes AWS instances felt faster for package installs, and that Azure is the cloud he associates with data pipelines. Jenkins itself can also be run as a Docker container or inside Kubernetes. The UI is the same.

GitHub Action. A YAML workflow in the repo. GitHub runs it when the on: event happens, such as a push.

072 — GH Jenkins

  • He copies GitHub’s “publish a Docker image” workflow. Trigger is push to master. The job checks out the repo, logs in to Docker Hub, and builds and pushes.

  • The CD half is a second job, or extra steps, that SSH to the VM and run docker stop, docker rm, docker pull, and docker run of docker.io/<user>/edward:master. Two jobs in parallel can deploy before the push finishes. He puts the SSH steps after the push in one job so they run in order.

  • CircleCI is the external CI. He signs up with GitHub, authorises the organisation, and picks the edward-jenkins repo. The free tier runs one job at a time.

Orb. A CircleCI package of ready-made steps, such as the Docker login, build, and push.
